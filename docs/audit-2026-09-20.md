## Existing strengths

The repository already has independent raw/clean validation, explicit conversation membership, preserved parent graphs and source spans, frozen review inventories, separate prepared/reviewed/integrated states, evidence-bearing decisions, and journaled installation with stale-hash checks. Historical summary counts are deliberately not equivalent to original-message review coverage. These are useful engineering foundations and should not be replaced by a large agent framework.

## Residual risks and prioritized acceptance criteria

### P0 — Before autonomous master promotion

**Legacy writer locking.** `reconciliation.apply` checks hashes and journals but does not itself acquire a shared cross-process master lock. The new controller lock covers only its own state directory. Keep a single operator/writer for now. Add a lock keyed to the canonical archive, held from preflight through final verification; test competing different-run writers, crashes, stale patches, and recovery. Do not claim multi-file atomicity: per-file replacement plus a recovery journal is the existing guarantee.

**Semantic promotion.** A quotation existing does not prove its interpretation or attribution. Candidate files must not automatically become accepted master entries. Add a review/promotion contract referencing candidate hashes, full relevant source context, existing entry IDs, and explicit dispositions. Check evidence within the linked entry rather than relying only on document-wide presence. Owner-confirmed corrections must retain precedence and historical wording.

**Runtime isolation.** CLI read-only settings do not prevent every read/exfiltration possibility. Test an isolated account or VM, inspect managed integrations, restrict mounts and destinations, and use synthetic adversarial text before real unattended operation. The new tests do not establish security against arbitrary prompt injection.

### P1 — Before claiming quality or incremental operation

**Cross-export identity.** Evidence IDs include the source-payload hash, so a new export can change identities even for unchanged messages. This release skips already reviewed pieces in the same frozen run; it does not reconcile two export versions. Introduce a separate logical occurrence key using provider, original conversation identity and graph position, and compare exact content, ancestry and membership. Test reordered exports, reused IDs, branches, changed messages, and newly available attachments. Preserve uncertain matches for review.

**Semantic evaluation.** Build an independently annotated, invented/consented corpus with drafts, quoted first-person text, dreams, assistant speculation, multilingual continuations, branches, missing media and contradictions. Report source-supported precision, salient-fact recall, attribution error, appropriate abstention and false merges separately from schema validity. Use a fixed holdout and document annotation disagreements. A deterministic demo is not an LLM quality benchmark.

**Budget completeness.** Current limits apply per controller state. Token thresholds can overshoot one call and unknown usage blocks progress. Dollar prices, subscription credits, global quotas and model quality per cost are not measured. Add operator-approved retry records that retain previous attempts, and a cross-run usage ledger before allowing many simultaneous runs.

### P2 — Usability after the trust boundary is solid

Add retrieval of relevant master entries with a transparent lexical baseline before embeddings; evaluate recall and false matches. Introduce a read-only local review interface or SQLite/FTS index only when it solves a measured navigation problem. Profile repeated full source hashing before optimizing; retain change detection and independent validation. Require passing CI and reviewed pull requests on the default branch; it was unprotected at audit time.

## Claims to avoid

Do not claim fully autonomous master completion, cross-export incremental processing, zero hallucinations, a hard dollar budget, clinical accuracy, or completed Claude/media coverage. Describe what this commit demonstrates: a traceable importer/reconciler with a bounded, resumable, candidate-only Codex extraction extension and reproducible synthetic failure tests.
